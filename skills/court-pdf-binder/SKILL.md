# Court PDF Binder — 전자소송 증거 종합 바인더

표찰(`stamp_evidence.py`)이 끝난 서증 PDF들을 **호증 순서대로 병합**하고,
북마크(계층형 TOC)를 넣어 열람 가능한 합본을 만든다. ECFS 개별 첨부파일
용량 한계(기본 50MB)를 넘으면 자동으로 권을 나눈다.

## 핵심 도구

```bash
${PLUGIN_ROOT}/scripts/py ${PLUGIN_ROOT}/scripts/bind_court_pdf.py \
    --input-json evidence.json -o 증거바인더.pdf --max-mb 50
```

입력 JSON은 증거설명서와 같은 형식(evidence_list 호환):

```json
[
  {"label": "갑 제1호증", "title": "차용증", "file": "갑제1호증.pdf"},
  {"label": "갑 제2호증", "title": "계좌거래내역", "file": "갑제2호증.pdf"}
]
```

## 동작

- **북마크 트리**: 각 증거의 시작 페이지에 `[갑 제1호증 차용증]` 형태의
  레벨 1 북마크를 삽입한다. 재판부가 합본에서 바로 호증으로 점프할 수 있다.
- **용량 자동 분할**: 누적 크기가 `--max-mb`를 넘으면 다음 증거부터 새 권
  (`증거바인더_2권.pdf`)으로 나눈다. 경계 판정은 원본 파일 크기 누적 기준의
  보수적 계산이므로 실제 출력이 한계를 넘지 않는다.
- **증거 누락 엄격 모드**: 목록의 파일 하나라도 없으면 전체를 중단한다
  (exit 2) — 빠진 증거가 있는 합본은 만들지 않는다.

## 전자소송 규격 가이드

- 첨부 순서는 증거설명서의 서증부호 순서(갑 제1호증 → …)와 일치시킨다.
- 분할이 발생하면 권 구성을 증거설명서 비고란에 명기한다(예: "갑 제5호증부터
  2권").
- 바인더 합본은 **편집본**이다 — 원본 각각의 SHA-256은 그대로 증거설명서에
  기재하고, 합본 자체의 해시가 필요하면 `certify_evidence_file.py`로 별도
  인증한다.
