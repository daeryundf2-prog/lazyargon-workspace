# Korean PII Masker — 한국형 개인정보 비식별화

법원 제출본·공문서·분석 보고서에 남은 개인정보를 결정적으로 마스킹한다.
체크섬 검증까지 수행하며, 처리 통계는 스크립트가 산출한다(SSOT).

## 핵심 도구

```bash
${PLUGIN_ROOT}/scripts/py ${PLUGIN_ROOT}/scripts/mask_korean_pii.py 증거설명서.md -o 제출용.md --report 비식별리포트.md

# 주민번호·전화만
${PLUGIN_ROOT}/scripts/py ${PLUGIN_ROOT}/scripts/mask_korean_pii.py 데이터.csv --types rrn,phone
```

## 마스킹 규칙

| 유형 | 원본 | 마스킹본 |
|---|---|---|
| 주민등록번호 | 901212-1234561 | 901212-1****** |
| 외국인등록번호 | 901212-5678901 | 901212-5****** |
| 전화/휴대폰 | 010-1234-5678 | 010-1234-**** |
| 카드번호 | 4111-1111-1111-1111 | ****-****-****-1111 |
| 계좌번호 | 123-45-678901 | ***-**-**8901 |
| 이메일 | hong@example.com | h**@example.com |
| 여권 | M22000000 / M123A4567 | M******** |
| 운전면허 | 12-34-567890-12 | 12-34-******-** |

- 주민번호는 **체크섬 검증**을 병행한다. 체크섬이 틀린 형식값도 마스킹하되
  리포트에 "불일치 N건"으로 표시해 원본 확인을 유도한다(오탐 경보).
- 주민번호 구분자는 `-`, 공백, 점, 무구분자(13자리 연속)까지 인식한다.
  단 **무구분자 후보는 체크섬 통과분만 마스킹**하고 불일치는 "의심"으로
  보고만 한다. `--mask-suspect-rrn`으로 강제 마스킹 가능.
- 휴대폰은 구분자 생략(`01012345678`)도 잡는다. 유선 무구분자는 오탐이
  커서 `--types landline_nodelim` 지정 시에만 동작한다.
- 카드번호는 Luhn 체크섬 통과분만 마스킹한다.
- 계좌는 3~5그룹을 지원하고 끝 4자리만 남긴다.
- 날짜(2024-01-16)는 계좌번호로 오탐하지 않도록 판별해 유지한다.
- `--vault v.pii-vault.json`으로 가역 토큰 치환, `--unmask --vault`로 복원.
  vault 파일은 비밀 취급(`.gitignore` 등록됨).

### opt-in 유형 (기본 off — `--types`에 명시해야 동작)

| 유형 | 탐지 방식 | 마스킹본 |
|---|---|---|
| `landline_nodelim` | `0212345678` 무구분자 유선 | 02-1234-**** |
| `name` | 라벨(`성명:`/`피고인` 등) + 호칭(`~님`/`~씨`/`~귀하`) + 성씨 사전 | 김** (성씨 보존) |
| `address` | 시도+시군구+도로명/지번 구조 (번지·호수 필수) | 서울특별시 *** |

- 이름·주소는 **휴리스틱**이다 — 성씨 사전(80여 성)과 라벨/호칭 앵커에
  의존하므로 외국 성씨·비정형 표기는 놓치고, 드물게 오탐된다.
  직함·역할어(사장님·고객님·담당자님 등)는 블록리스트로 제외한다.

### 지원하지 않는 형식

- 구분자 없는 유선전화(`0212345678`) — 기본 off, `landline_nodelim` 옵션 필요
- 사업자등록번호·법인등록번호 — 계좌 형식과 겹쳐 함께 마스킹될 수 있으나
  별도 유형으로 분류하지는 않는다
- 라벨·호칭 없는 나형 이름(“김철수가 말했다”의 비앵커 단독 명명) — opt-in
  `name`도 앵커가 필요하다. 완전한 커버리지는 아래 ko-pii 참조

## 한계 — 반드시 고지

- **이름·주소 탐지는 휴리스틱 옵션이다** (`--types name,address`). 앵커 없는
  이름·비정형 주소는 탐지하지 못한다. 더 넓은 커버리지가 필요하면 사전 기반
  라이브러리([ko-pii](https://github.com/Marker-Inc-Korea/ko-pii),
  MIT — 룰·체크섬·가명 Vault 33카테고리)를 보강으로 검토하고, 최종 제출본은
  사람이 1회 더 훑어야 한다.
- HWPX/HWP 원본 서식을 보존한 마스킹은 kordoc MCP의 `redact_document`가
  담당한다. 텍스트 레이어는 본 스크립트, 서식 문서는 kordoc으로 분업.

## 워크플로

1. `generate_evidence_doc.py` → 증거설명서 생성
2. `mask_korean_pii.py` → 제출본 비식별화 + 리포트
3. 제출 전 `audit_evidence_integrity.py`로 해시 대조(비식별본은 원본과 해시가
   다르므로, 어느 쪽 해시를 증거설명서에 기재했는지 혼동하지 말 것 — 원본 해시
   기재가 원칙, 비식별본은 별도 관리)
