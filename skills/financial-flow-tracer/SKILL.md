# Financial Flow Tracer — 금융 거래내역·계좌추적 분석

수백~수만 행 거래내역에서 **누가 얼마를 주고받았는가**(랭킹), **짧은 기간에
돌고 돈이 있는가**(순환 의심), **들어온 돈이 어디로 갔는가**(홉)를 결정적
스크립트로 산출한다. 집계는 LLM이 아니라 코드가 하며 — 금액 계산을 LLM에
맡기면 반드시 틀린다.

## 핵심 도구

```bash
# CSV (은행 내려받기 표준 형식 — utf-8/cp949 자동 판별)
${PLUGIN_ROOT}/scripts/py ${PLUGIN_ROOT}/scripts/trace_financial_flow.py 거래내역.csv -o 자금흐름.md

# XLSX (openpyxl 필요) + 순환 판정 창 3일
${PLUGIN_ROOT}/scripts/py ${PLUGIN_ROOT}/scripts/trace_financial_flow.py 거래내역.xlsx -o 자금흐름.md --window-days 3
```

열 이름은 자동 인식한다(거래일시/일자, 입금액/출금액, 상대방/적요 등 —
스크립트 docstring의 키 목록 참조). `금액` + `구분(입금/출금)` 형태도 지원.

## 산출물

1. **총 입출금 요약** — 기간, 건수, 총액
2. **상대방별 랭킹** — 거래 규모 순, 입금합·출금합·건수
3. **자금 순환 의심** — 동일 상대방에게 출금한 뒤 `--window-days` 이내에
   재입금받은 쌍(댕글링형 순환의 기본 신호)
4. **단기 홉** — 입금원 → 본 계좌 → 출금처 연결(수취 직후 송금 패턴)
5. **Mermaid 흐름도** — 상위 상대방 중심의 자금 이동 그래프

## 분석의 한계 (반드시 사용자에게 고지)

- 입력은 **계좌 명세 하나**다. 상대방 계좌의 내부 흐름은 명세에 없으므로
  "A→B→C 완전 경로"는 단일 명세로는 증명할 수 없다 — 홉 표시는 의심
  패턴이지 결정적 증거가 아니다.
- 상대방 이름은 은행이 기재한 문자열이다(개인명·상호·단말기명 혼재).
  동일인이 여러 이름으로 기재될 수 있어 랭킹 과소·과대 계상이 가능하다.
- 위법성(자금세탁 등) 판단은 법률 전문가 영역이다. 본 스킬은 통계를 낼 뿐이다.

## 실무 팁

- 복수 계좌가 있다면 계좌별로 보고서를 만들고, 홉 표의 상대방이 다른 계좌
  보고서의 랭킹에 나타나는지 사람이 연결한다.
- 의심 표의 원본 근거는 원본 행 번호(`row` 필드 기준, 헤더 포함)로 추적한다.
- 실명·계좌번호 등 개인정보는 보고서 공유 전 비식별화한다(kordoc
  `redact_document` 연동 가능).
